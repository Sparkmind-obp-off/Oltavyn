# OLTAVYN — Roadmap

**Status:** Proposed sequence; gates matter more than calendar dates.

## Phase 0 — Foundation (current)
- Product definition, North Star, MVP scope and architecture documents.
- Record assumptions, data handling and integration boundaries.
- Define test protocol and a small set of real-user conversations/observations.
**Exit:** scope and safety boundaries are understood; no claim of market validation.

## Phase 1 — Evidence prototype
- Workspace settings for niche, audience, goal and permitted sources.
- Add evidence manually or import a small authorized dataset.
- Evidence list with URL/reference, timestamp, quote/summary, source type and confidence/limitations.
- Simple opportunity cards linked to evidence; transparent scoring rubric.
**Exit:** a reviewer can trace every opportunity claim back to evidence and reject weak candidates.

## Phase 2 — Content workbench
- Generate structured brief and a small set of content variants from a selected opportunity.
- Show which evidence supports which claims; mark unsupported statements for review.
- Edit, version, approve/reject, and export content.
**Exit:** user can approve a useful asset and understand its provenance.

## Phase 3 — Experiment log and learning
- Record intended channel, publication status/URL/time and experiment hypothesis.
- Enter or import observed metrics with units, source and time window.
- Compare experiments and recommend a next test with explicit reasoning and uncertainty.
**Exit:** one complete evidence-to-learning loop can be demonstrated end to end.

## Phase 4 — Authorized channel integration
- Select one channel only after API permissions, terms, account eligibility and costs are verified.
- OAuth/token handling, preview, explicit approval, idempotency and audit log.
- Keep manual publish path available if integration fails.
**Exit:** test account confirms authorized operation; publishing is never silently triggered.

## Phase 5 — Repeatability and expansion
- Improve onboarding and usability from observed sessions.
- Add another source/channel only when the first is reliable and demand is demonstrated.
- Add team roles, scheduling or richer analytics only when justified by evidence.
**Exit:** repeated usage and measurable user value, not merely a larger feature list.

## Priority rule
Choose work by user pain, evidence quality, risk reduction and ability to complete a loop. Avoid parallel platform integrations and premature autonomous agents. No dates are committed until capacity, access and constraints are confirmed.
